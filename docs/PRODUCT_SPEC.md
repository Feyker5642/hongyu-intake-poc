# PRODUCT_SPEC — AI 詢價轉單助手

Status: fixed for the 2026-08-14 interview build
Updated: 2026-08-12

## 它解決的問題

客戶從網站表單、Email、LINE、電話紀錄、圖片或 PDF 丟來一段**不完整**的需求
之後，業務必須重新閱讀、整理、追問、再 key 進系統。宏宇現有公開詢問頁只收
「姓名／公司、電話、需求項目、詳細描述」——正好是 AI 結構化之前的原始輸入。

## 定位

**ERP 前面的詢價整理層。** 不是報價系統、不取代 ERP、不要求客戶填二十格。
Concept Demo／非正式報價系統。

```
宏宇現有網站表單／Email／LINE／PDF／圖片
              ↓
        AI 詢價轉單助手
  需求抽取 → 欄位整理 → 缺漏檢查
              ↓
        業務人工修改確認
              ↓
詢價規格單／追問訊息／JSON／(未來) ERP 草稿
```

## 關鍵前提（修正過的假設）

印刷包裝的客戶需求欄位**不是一套固定表格**：共通欄位＋各產品類型專屬欄位。
名片要紙材尺寸、書冊要頁數裝訂、大圖要材質安裝、禮盒要盒型內襯板材。
第一版只完整支援**紙盒／彩盒／禮盒**——它最能同時展示自由文字理解、單位
標準化、材質分類、後加工辨識、缺漏檢查、結構化 JSON、人工確認與未來 ERP
串接。其餘品類只顯示為「後續可新增的產品模組」。

## 網頁（單頁三區）

1. **原始需求**：貼上文字／載入合成範例（P1：上傳 PDF/圖片）／解析按鈕。
   頁面常駐三項標示：**Concept Demo**、**全部使用合成資料**、**非正式報價**，
   並提醒：請勿輸入真實客戶個資或機密價格。
2. **AI 結構化結果**：可編輯欄位（不是唯讀文字）。每欄標記狀態：
   已確認／AI 抽取／不確定／未提供。重要欄位附原文依據。
3. **檢查與下一步**：資料完整度 n/m、待補清單、風險提示（如：內容物尺寸
   ≠ 成品尺寸，不可直接沿用）。動作：產生客戶追問訊息（P0）／人工確認（P0）／
   匯出 JSON（P0）／產生內部詢價規格單（**P1**）／CSV 匯出（**P1**）。
   **人工確認後**才顯示「ERP 草稿資料已準備」；不真的連 ERP。

## 面試展示說法（口徑）

先研究宏宇公開需求表單，比對台灣包裝業公開詢價欄位、材質與製程資料；
Demo 欄位皆有公開依據（見 PUBLIC_SOURCES），**不假設**宏宇的價格、材料庫存、
供應商或 ERP 結構。定位為 ERP 前的詢價整理層：自然語言 → 標準欄位 → 缺漏
與衝突 → 業務確認 → 交給 Excel／資料庫／ERP 的 JSON。進公司後先確認最常見
產品、現有報價表、ERP 品牌與欄位，再接公司的材料、工序與價格規則——
不用 AI 猜一個看起來合理的價格。
